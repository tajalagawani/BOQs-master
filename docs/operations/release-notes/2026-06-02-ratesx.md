# Release v0.3.0 — RatesX construction-rates intelligence

**Released:** 2026-06-02
**Commit range:** `eec681a..HEAD`
**Staging URL:** http://20.203.125.83/rates

## Headline

RatesX graduates from a raw upload surface to a full construction-rates
warehouse. This release lands the v2 normalized star schema (30 tables),
the POMI → NRM classification pipeline over a 604-entry RICS NRM2 bridge,
an inflation engine, and a faceted **Elemental-by-Project** analytics
workspace with composition and log-scale distribution views.

It bundles the prior `feat: implement rates upload functionality`
commit (parsers + per-tab schema contract) with the new normalization,
classification, and analytics layers built on top of it.

## What's in this release

### Rates v2 warehouse

- New normalized star schema in `web/prisma/schema.prisma` and
  `web/prisma/migrations/manual/rates_v2/migration.sql`: **24 dimension
  tables + 1 lineage table (`RatesUploadV2`) + 5 fact tables**, plus a
  junction side-table and a family of `v_rates_*` flattening views.
- `RatesFactRateItem` (~15,500 rows) fans out to 12 foreign keys and
  carries a Postgres `description_tsv` full-text column,
  `confidence`, `isOutlier`, and a `classificationStage` field.
- Full provenance: every fact row cascade-links to the upload, section,
  and tab that produced it — audit- and GDPR-ready by construction.

### Ingestion + classification pipeline

- Workbook upload + parse at `app/api/rates/uploads/route.ts` with a
  family-detecting parser layer (`modules/rates/lib/parsers/*`) and the
  per-tab schema contract in `modules/rates/lib/schemas.ts`.
- `scripts/backfill-rates-v2.ts` — idempotent v1 → v2 explode (interns
  dimensions, emits facts).
- `scripts/classify-rate-items-from-bridge.ts` — TF-IDF classification
  of every rate item against `pomi_to_nrm_corrected.json` (604 entries,
  RICS NRM2) into POMI section + NRM L1, with `--dry / --reset /
  --threshold` controls.
- `scripts/derive-nrm-from-pomi.ts` — NRM-level derivation from POMI
  coding.

### Elemental-by-Project analytics

- New full-page workspace at `/rates/elemental-by-project`
  (`components/rates-home/ElementalWorkspace.tsx`).
- **Composition view** — per-project stacked NRM-element bars with an
  Absolute ↔ 100% toggle, a click-to-isolate legend, and a project
  detail drawer.
- **Distribution view** — per-element spread on a shared logarithmic
  axis (handles the 1k → 174k/m² range that no linear axis can), with
  min–max whisker, IQR band, per-project dots, and a median column.
- **Faceted, client-side filtering** — currency is a hard axis (one at a
  time), every filter option shows a live count, and empty combinations
  are hidden instead of silently producing a blank chart.
- Inflation engine (`modules/rates/lib/inflation.ts`) with a Raw ↔
  Adjusted toggle and reference-year strip.

### Data-quality fixes

- New manual migration
  `web/prisma/migrations/manual/rates_v2/fix_nrm_l1_labels.sql` —
  non-destructively repairs shredded NRM L1 element names on benchmarks
  (`"Internal"` / `"Walls and Doors"` → `"Internal Walls and Doors"`),
  19 rows + the unclassified bucket, with zero foreign-key moves and
  rate items untouched.
- Hardened `splitCodeLabel` in `load-benchmarks.ts` so the loader never
  re-shreds multi-word element names (splits only on explicit
  delimiters, never bare whitespace).
- Duplicate `(project, element)` benchmark rows now collapse to the mean
  of non-zero values in `projectElementValues`, so a per-m² rate is
  never double-counted across consumers.

### Documentation

- New module reference `docs/modules/ratesx.md` (A-to-Z: data model,
  pipeline, classification, inflation, elemental analytics, common
  edits, data-quality notes, file map) — matching the depth of the
  CostX and BOQs module docs.

## Known limitations

| Item | Workaround / Plan |
|---|---|
| Upload writes v1; analytics read v2 — new uploads don't appear until the backfill + classify scripts run | Run `backfill-rates-v2.ts` then `classify-rate-items-from-bridge.ts` after an upload; no automatic request-path trigger yet |
| `classificationStage` is `NULL` on all rate items despite ~99% being classified | Classifier does not yet write the stage; column exists |
| `RatesFactMaterialPrice` is empty | Materials/Commodities workbooks parse to v1 but aren't backfilled into the fact yet — material-price timeline shows no data |
| Country split `"UAE"` (160) vs `"United Arab Emirates"` (12); ~18 projects have null currency; `asset_type` null/place-names | Surfaced honestly via facet counts + exclusion notes; dimension cleanup is a pending data task |
| No semantic similarity | Classification is full-text/TF-IDF only; no pgvector/embeddings |
